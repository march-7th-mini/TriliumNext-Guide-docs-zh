## What is this

This project translates the official help documentation of [TriliumNext/Trilium](https://github.com/TriliumNext/Trilium) (the **Developer Guide**, **User Guide** and **Release Notes** directories under `docs/`) into Simplified Chinese.

The output is a 1:1 replica of the official structure, stored under `docs-zh/` in Trilium export format — ready to be zipped and imported into Trilium. Combined with the frontend navigation patch, the `?` help button in the UI automatically opens the Chinese version.

> Related discussion: [TriliumNext community · Chinese help documentation request](https://github.com/orgs/TriliumNext/discussions/10768)

## Features

| Feature | Description |
| --- | --- |
| Full translation | All three docs fully translated, 1:1 replica of the official tree, internal links preserved, importable separately |
| Built-in help redirect | Every translated note carries `#originalHelpNoteId=_help_<sourceNoteId>` + `#helpDoc=zh`, mapped 1:1 to the English version; the patch locates the Chinese version via these two attributes |
| Navigation patch | Help split-pane and quick-edit popup automatically switch to Chinese; falls back to English when no Chinese version exists (no flash) |
| Incremental sync | Weekly check against upstream; already-translated content is reused via hash comparison — only changed files are re-translated |

## Getting started

> 📥 **Downloads**: all attachments (the three doc zips and the navigation patch) are published on the **Releases page** (the **Releases** link on the right side of the repo homepage). Always download the latest version — release attachments are re-published as translations are updated.

### 1. Import the translated docs

Download `User-Guide.zip` (or all three doc zips) from **Releases**. Then, in Trilium: right-click anywhere in the left note tree → **Import** and select the downloaded zip.

> ⚠️ The `!!!meta.json` inside each zip must sit at the **zip root**. When packaging manually, zip the contents **inside** each doc directory (e.g. enter `docs-zh/User Guide` and zip everything there). Do **not** zip the whole `docs-zh/` folder as one archive — its root has no `!!!meta.json` and the importer will reject it.

![Import](https://github.com/user-attachments/assets/4c0a48d3-8827-44f8-95fe-ffe5ceb06160)

### 2. Import the navigation patch

Download `TriliumNext中文版帮助文档跳转补丁.zip` from **Releases**, and when importing it **make sure to uncheck "Secure import"**. It creates a JS frontend note (tagged `#run=frontendStartup`) that takes effect **after refreshing the page**.

> The patch is **required** for the built-in help (`?`) to jump to the Chinese version. If a document has no Chinese version yet, it gracefully falls back to the built-in English one.

### 3. Verify

- Click the `?` button in the top-right → the help split pane shows the Chinese doc directly.
- Open help links inside the quick-edit popup (right-click a note → open help) → they also redirect to the Chinese version.

## How updates work

A GitHub workflow checks upstream **every Sunday** (manual trigger also available under Actions).

```
upstream docs → sparse-checkout (3 doc dirs only) → hash comparison → translate only changed files → auto PR
```

- Already-translated content is **reused incrementally** via hashes, so updates are extremely cheap.
- Follow the PR log to track translation progress.
- ⚠️ Release zips may lag behind the actual translation state in this repo — re-download the latest attachments periodically and re-import.

## How it works

### The built-in help ID rule

Trilium's built-in English help note IDs equal `_help_` + the corresponding noteId in the GitHub docs tree (e.g. `_help_BOCnjTMBCoxW`).

The translation script appends two attributes to every translated note:

- `#originalHelpNoteId=_help_<sourceNoteId>` — which English help note it maps to
- `#helpDoc=zh` — marks it as Chinese help

The navigation patch uses these two attributes to redirect `?` help to the Chinese version.

### Internal links need no rewriting

Trilium export links are relative paths (resolved by `dataFileName`). The translated directories sit parallel to the English ones, so links automatically point at the translated files.

### Two-phase translation

1. **Initialization (`--init`)**: builds the tree, batch-translates titles, generates stable new IDs (`_zh_xxx`) and writes attributes. Bodies are still English at this stage — review the skeleton first.
2. **Body translation**: incremental; already-translated files are skipped by hash, so interrupted runs can simply be re-triggered.

> Why skeleton first? Titles and IDs are fixed and persisted first, so internal links in the bodies resolve stably to the Chinese notes; the skeleton PR also lets you review the structure before translating the bodies.

### How the patch works (V3)

```
Opening an English _help_* note (two entry points)
  · ? : contextual-help split pane
  · right-click / Ctrl+click: quick-edit popup (_popup-editor)
        ↓
Monkey-patch NoteContext.setNote (intercepts before the English note loads)
        ↓
Look up the Chinese version via #originalHelpNoteId
        ↓
Chinese exists → open the Chinese noteId instead (no flash)
        ↓
No Chinese version → open the English original as usual
```

The patch is pure frontend JS — **no backend scripting permission needed, no data sent anywhere**.

## FAQ

| Issue | Cause & fix |
| --- | --- |
| Import into Trilium fails | 99% of the time the zip structure is wrong: `!!!meta.json` must be at the zip root. Zip the contents of a single doc directory, never the whole `docs-zh` folder |
| `?` still shows English | The patch isn't active: check the script note has the `#run=frontendStartup` tag and the page was refreshed; or the doc has no Chinese version yet (it falls back to English) |
| Want to disable Chinese help | Temporarily: remove the `#run=frontendStartup` tag from the script note and refresh. Permanently: delete the script note and all Chinese help notes |

## Adapting this repo for other languages

Want to translate the docs into another language (or switch to a different translation model)? Only a few key spots in `translate_trilium_Guide_docs_CHS.py` need to change:

### 1. Target language (required)

The translation instruction in the script:

```python
prompt = (
    "你是一位专业的技术文档翻译。请把下面的英文 Markdown 文档翻译成简体中文。
"
    ...
)
```

Change "简体中文" to the target language (e.g. `日本語`, `한국어`, `Deutsch`). Keep the rest of the requirements: preserve Markdown structure, keep HTML `href` values untouched, don't translate code blocks, keep proper nouns in English.

### 2. Language attribute (required)

The `helpDoc` label written to every translated note is the language code the navigation patch matches on:

```python
attrs.append({"type": "label", "name": "helpDoc",
              "value": "zh", "isInheritable": False, "position": max_pos + 20})
```

Change `"zh"` to the target language code (e.g. `"ja"`, `"ko"`, `"de"`), and update the language code the navigation patch looks for accordingly, or the redirect won't match.

### 3. Output directory (optional)

```python
OUT_DIR = "docs-zh"   # e.g. "docs-ja", to keep languages separate
```

### 4. Switch the translation model (optional)

```python
MODEL = "deepseek-chat"                      # e.g. "gpt-4o-mini"
BASE_URL = "https://api.deepseek.com"        # e.g. "https://api.openai.com/v1"
```

### 5. Glossary (recommended)

The translation script auto-loads `glossary.tsv` (TAB-separated: source → target language) at startup and injects the top 60 terms into the prompt for consistent terminology (`GLOSSARY_FILE` / `GLOSSARY_INJECT` at the top of the script; skipped automatically if the file is missing):

```python
GLOSSARY_FILE = "glossary.tsv"   # Weblate glossary (optional, skipped if missing)
GLOSSARY_INJECT = 60             # max terms injected into the prompt
```

`glossary.tsv` is generated from the official Weblate by the glossary builder — update its language setting and regenerate when adapting languages:

```python
# build_glossary.py
LANG = "zh_Hans"      # Weblate language code of the target language, e.g. "ja", "ko", "de"
PROJECT = "trilium"   # Weblate project name (default trilium, usually unchanged)
```

```bash
python3 build_glossary.py     # regenerate glossary.tsv (--dry fetches without writing)
```

> If the target language has no glossary on Weblate, just delete `glossary.tsv` — the script skips it and translation still works.

### 6. Navigation patch (case-dependent)

The patch JS looks up translated notes by the `#originalHelpNoteId` attribute — **it is language-agnostic**. As long as the translated notes carry that attribute, it works as-is for a single-language setup.

Only when **multiple languages coexist** (e.g. Chinese and Japanese versions of the same doc) can `api.searchForNotes` return several hits — the patch takes the first one and may redirect to the wrong language. In that case, add a language filter to the query in the patch JS:

```js
// TriliumNext中文版帮助文档跳转补丁.js → findChinese()
const query = '#originalHelpNoteId = "' + englishNoteId.replace(/"/g, '\\"') + '"' +
              ' AND #helpDoc = "target-language-code"';   // e.g. "ja"
```

Then re-zip and re-import.

### Related configuration

| Issue | Cause & fix |
| --- | --- |
| Actions error "LLM_API_KEY not found" | Add `LLM_API_KEY` under repository Settings → Secrets and variables → Actions (a `sk-` key from DeepSeek / OpenAI); the workflow injects it into the script |
| Translation failed halfway / timed out | Just re-run the workflow — the script keeps state (`.translated.json`) and skips already-translated files (incremental resume) |
| Don't want the weekly auto-run | Remove the `schedule:` lines from the workflow, keeping only the manual trigger |
| Why not fork the official repo | A fork would copy thousands of source files; the workflow uses sparse-checkout to fetch only the three doc dirs. Same applies when adapting for another language — just edit the script |
