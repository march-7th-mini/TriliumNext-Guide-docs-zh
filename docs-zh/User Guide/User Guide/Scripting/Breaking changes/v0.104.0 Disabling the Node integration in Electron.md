# v0.104.0：在 Electron 中禁用 Node 集成
## 简介

在 v0.104.0 之前，在渲染器级别执行的代码（例如前端脚本）可以直接 require `@electron/remote`，甚至可以直接使用 Node.js API（例如 `process` 或 `fs`）。虽然这让它们功能强大，但也暴露了相当大的攻击面——笔记中的任何 XSS 或不可信脚本都会变成宿主机上的远程代码执行。

为了缓解这一问题，客户端不再拥有对这些 API 的访问权限，所有操作都必须改为通过 <a class="reference-link" href="../Script%20API/Electron%20API.md">Electron API</a> 进行。

> [!NOTE]
> 如果此 API 变更导致你的某些前端脚本出现问题，可以考虑：
> 
> *   与 <a class="reference-link" href="../Backend%20scripts.md">后端脚本</a> 交互，后者拥有更大的自由度。
> *   [报告](../../Troubleshooting/Reporting%20issues.md) 该问题作为功能请求。

## API 概览

前端和后端 API 位于全局变量 `api` 中，可以在脚本的任何位置使用。例如，要向用户显示一条消息，可以使用以下前端脚本：

```javascript
api.showMessage("Hello world.");
```

Electron API 则不同：它位于 `window.electronApi` 上（由桌面预加载脚本暴露），而不是在 `api` 上，并且仅在 Electron 桌面构建中可用。使用它的前端脚本应通过 `if (window.electronApi)` 进行防护，以便在浏览器和独立（WASM）构建中能够平稳降级。

```javascript
window.electronApi?.window.setZoomFactor(1.2);
```

## 额外保护

部分 API 内置了额外的安全防护措施，以防止未经授权的访问。

`shell` 组是校验最严格的：`openExternal` 被限制在一组允许列表中的 URL scheme（阻止 `file:`、`smb:`、Follina 类 scheme 等），`openPath` 必须解析到 Trilium 数据目录或临时目录下，而 `downloadURL` 被锁定为应用自身的源。无效输入会在主进程侧抛出异常，而不是被静默传递。
