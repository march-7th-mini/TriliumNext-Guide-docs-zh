# Microsoft OneNote
Trilium 允许从 OneNote 导入。目前唯一支持的机制是通过 Microsoft Graph API，这需要你在浏览器中进行身份验证，以便 Trilium 获取笔记。

## 导入过程

1.  在<a class="reference-link" href="../../UI%20Elements/Note%20Tree.md">笔记树</a>中，右键单击并选择 _导入到笔记中_。
2.  在 _导入来源_ 部分，选择 _OneNote_。
3.  按下 _连接_ 按钮：
    1.  在桌面应用中，你将被重定向到 Microsoft 的身份验证页面，在那里你可以登录你的账户。
    2.  在 Web 应用中，过程稍微复杂一些，因为它需要将代码复制到剪贴板、访问链接、粘贴代码，然后再次登录。
4.  连接成功后，你应该能够看到可以导入的分区列表。只需勾选要导入的分区，然后按下 _导入所选内容_ 按钮。
5.  等待导入完成。

## 支持的功能

Trilium 在导入过程中会保留以下功能：

*   基本格式（粗体、斜体、下划线、删除线、下标、上标、字体大小、标题、颜色、高亮）。
    *   黑色文本会被有意去除，以便在深色主题下正常工作。
*   行内代码会被自动检测并格式化。使用代码样式的段落也会被转换为<a class="reference-link" href="../../../Note%20Types/Text/Developer-specific%20formatting/Code%20blocks.md">代码块</a>。
    *   遗憾的是，代码的缩进可能会丢失，因为 Microsoft API 返回的数据中根本不包含该信息。
*   具有不同项目符号类型的<a class="reference-link" href="../../../Note%20Types/Text/Lists.md">列表</a>。
*   <a class="reference-link" href="../../../Note%20Types/Text/Tables.md">表格</a>
    *   单元格背景会被保留，包括尽力进行的色相校正，因为 Graph API 返回的颜色有时不正确。
    *   单元格宽度也会按比例保留，唯一的区别是 Trilium 中的表格使用基于百分比的宽度，而不是固定的像素尺寸。
*   图片和<a class="reference-link" href="../../Notes/Attachments.md">附件</a>。
    *   自 v0.104.1 起，屏幕剪辑也得到正确支持，将其时间戳显示为图注。
*   待办事项列表
*   手绘内容会被保留，并在笔记内以 SVG 图片形式显示
    *   OneNote 的默认颜色（黑色）比较特殊，因为它在深色主题下也会渲染为白色。自 v0.104.1 起，这也通过使用一种特殊的 SVG 调整来支持，该调整会响应浅色/深色主题。
*   其他已导入页面之间的链接，如果链接文本与页面名称匹配，则转换为<a class="reference-link" href="../../../Note%20Types/Text/Links/Internal%20(reference)%20links.md">内部（引用）链接</a>，否则转换为普通链接。如果页面不属于导入范围，则保留原始的 `onenote:` 链接。
*   标签（待办事项列表除外）通过将其转换为[行内图标](../../../Note%20Types/Text/Insert%20buttons/Icons.md)来保留，这些图标可以通过图标名称进行搜索，并且可以像任何其他图标一样重新着色。部分图标会被转换为表情符号。

关于笔记结构：

*   分区内页面的顺序会被保留。
*   子页面和分区组通过将笔记嵌套在层级结构中来保留。
*   笔记和分区的创建和修改时间会被保留。分区或分区组的顺序不会被保留（参见限制）。

## 错误管理与报告

OneNote 导入器使用 Microsoft 的 Graph API，该 API 处理 HTML 导出（我们随后会对其进行后处理以供 Trilium 使用）。Graph API 本身必须先处理 OneNote 页面，然后才能发送给我们，因此这是一个耗时的操作，与笔记数量以及笔记的复杂性/大小成正比。

如果 Graph API 检测到过多操作，它会限制访问。导入器会考虑到这一点，但有时这意味着大部分时间都花在等待 Graph API 解除访问限制上，而不是实际导入数据。

此外，某些页面可能会因为 Graph API 端的内部超时或其他问题而在该层级失败。Trilium 会尝试重新获取页面以避免这种情况，但有时即使多次重试也无法检索到页面。在这种情况下，导入器仍会在 Trilium 中创建相应的笔记，但内容会替换为错误报告。这样可以保留<a class="reference-link" href="../../../Note%20Types/Text/Links/Internal%20(reference)%20links.md">内部（引用）链接</a>，并便于识别和手动修复失败的页面。

导入结束时，名为 _OneNote 导入_ 的顶层笔记将包含有关导入进行情况的信息：

*   已导入的笔记数量；
*   成功率；
*   无法导入的笔记列表，以及失败原因；
*   图片/附件下载失败的页面
*   导入在等待限流解除上花费了多长时间。

为了避免导入从根本上失败的情况（例如登录过期），如果连续 6 个页面导入失败，导入将报错退出。

## 属性

从 OneNote 导入的页面具有一些内置的[标签](../../../Advanced%20Usage/Attributes/Labels.md)：

*   `oneNotePageId`，对应 OneNote 中的页面 ID。这可用于识别原始的 OneNote 页面。Trilium 目前不会以任何方式使用它。
*   `oneNoteImportFailed` 附加到无法导入的笔记上。这可用于快速<a class="reference-link" href="../../Navigation/Search.md">搜索</a>失败的笔记。

## 限制

### 关于 OneNote 的自由格式结构

OneNote 在结构上与 Trilium 根本不同，因为它允许手绘与文本共存，并且文本框可以放置在文档中的任何位置（例如，一个常见的用例是分栏）。Trilium 对<a class="reference-link" href="../../../Note%20Types/Text.md">文本</a>笔记采用文档流机制，这意味着它无法自由定位。

为了应对这种差异，Trilium 会将文本结构展平为普通段落。段落将根据文本框的原始位置按视觉顺序排列，但它们的水平位置不会被保留。诸如分栏之类的并行文本可能会出现交错，从而引发问题。

此外，OneNote 中的绘图可以与文本框交错。Trilium 中的文本笔记不允许此功能，因此所有绘图都会出现在末尾。对于某些用例（例如图表），这没有问题，但如果你有高亮或其他依赖文本的绘图，它们将出现顺序错乱。

> [!NOTE]
> 有计划通过将绘图密集且与文本框交错的笔记转换为<a class="reference-link" href="../../../Note%20Types/Canvas.md">画布</a>来支持它们。

### 受密码保护的分区

OneNote 支持分区级别的加密；当导入包含这些密码保护分区的笔记本时，Trilium 将无法读取受密码保护分区的内容，因此它们会显示为空。这不是 Trilium 的限制，而是源（Graph API）根本不提供该信息。

分区本身会被保留以供参考，所有无法导入的分区都会显示在报告中（名为 _OneNote 导入_ 的顶层笔记）。

要在 OneNote 桌面版中取消保护分区，请右键单击受保护的分区 → _密码保护此分区_，然后按下 _删除密码_ 并同步。然后重新导入受保护的分区，或者删除所有内容并从头开始导入。

## 其他限制

以下是由于信息来自导入源（Microsoft Graph API）的方式而导致的已知限制，这意味着它们无法被修复。

*   分区（和分区组）的顺序不可用，分区改为按创建日期排序。
*   修订历史。
*   段落缩进，以及代码块缩进。
*   分区颜色。
*   标题内的绘图，标题可能会显示不完整或显示为“无标题”。

## 报告问题

导入笔记时，你可能会发现某些文本未正确渲染或结构未正确保留。只要此问题不是根本性问题（例如手写文本无法精确保留的问题），就建议[报告它](../../../Troubleshooting/Reporting%20issues.md)。

报告时，请确保提供以下信息：

*   再次导入该分区，在导入前勾选调试复选框。这会保留来自 OneNote 云 API 的原始文档（以及手绘数据，如果有的话），以便用于比较。
*   仅将受影响的页面导出为 ZIP，确保不会意外暴露任何敏感信息。
*   截取笔记在 OneNote 中的外观以及它在 Trilium 中最终呈现的截图。
*   将 ZIP 和截图附加到问题报告中。
