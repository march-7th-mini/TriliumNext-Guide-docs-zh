# 克隆笔记
## 动机

Trilium 的核心功能是能够将你的笔记组织成层级化的树状结构。

因此，你将会拥有一个精细而深入的笔记层级结构——每个子树都代表你知识库中一个更精细、更专业的视图。

这是一种非常强大的方法，但它也隐含了一个假设，即每个“子主题”都“归属于”一个父级。我用一个例子来说明——假设我的基本结构是这样的：

*   技术
    *   编程
        *   Kotlin
        *   JavaScript
    *   操作系统
        *   Linux
        *   Windows

现在，我开始学习 [Bash](https://en.wikipedia.org/wiki/Bash_\(Unix_shell\)) 并想创建与此主题相关的笔记。但此时我面临一个问题：该把它归类到哪里。问题在于，Bash 既是一种编程语言，也是一个与 Linux 密切相关的工具（shell）。它似乎同时属于这两者，我无法（也不想）在两者中做出选择。

## 解决方案

上述问题的解决方案是允许笔记拥有多个父级。

我称之为“克隆”，但这有点误导——并不存在原始笔记和克隆笔记之分——两个父级分类中的笔记是完全相同的。

关于“克隆”另一个容易误导的地方是，它暗示笔记被复制了一份。事实并非如此，笔记本身只有一个原始版本，它只是在树状层级中的多个位置被引用。因此，在一个分类中修改它，会同时改变所有其他分类中的它，因为它们都是同一条笔记。

以下是使用克隆后的最终结构：

*   技术
    *   编程
        *   Kotlin
        *   JavaScript
        *   Bash
            *   一些子笔记……
    *   操作系统
        *   Linux
            *   Bash
                *   一些子笔记……
        *   Windows

所以现在“Bash”子树出现在层级中的多个位置。两个 Bash 子树是相同的，包含相同的子分类和笔记。

## 删除笔记/克隆

对于克隆，删除的工作方式可能不是那么一目了然。

如果你尝试删除一条笔记，其工作方式如下：

1.  如果该笔记有多个克隆，只删除当前这个克隆，保留实际笔记（及其其他克隆）不变。
2.  如果该笔记没有任何其他克隆，则删除该笔记
    *   对其所有子笔记从第 1 步开始执行整个流程
