在这个版本中，文本笔记不再是一份单一的文档。笔记可以被嵌入、引用和在其他笔记中引用，并可在其出现的位置进行编辑，可以按列和标签页进行布局，还可以与绘图、附件和视频混合使用。文本笔记中的表格获得了此前缺失的工具，从合并单元格到排序，而旧版布局在新布局取代它一年之后被移除。

在编辑器之外，所有人都会用到的应用部分也进行了重建：上下文菜单和笔记自动补全、完整搜索和跳转对话框、启动栏和笔记树。共享页面重新看起来像应用本身，并以各自的视图渲染集合，日历和地理地图集合也获得了看板早已拥有的属性对话框。

AI 集成变得可以放心地用于真实数据库：每次工具调用在读取或更改笔记之前都会先询问，ChatGPT Codex 订阅可以替代 API 密钥，本地模型可以通过你选择的搜索引擎获得网络搜索能力。在手机上，iOS 有了新的布局，两个应用都可以在没有侧边栏的情况下导航。

## 💡 主要亮点

### 文本编辑器变成了块编辑器

文本笔记过去是一份文档：一整块富文本，其他笔记只能通过链接访问。现在它变成了一个组合体。一条笔记可以嵌入另一条笔记并让你在其所在位置进行编辑，可以引用它的几个块并保持引用为最新，或者指向它的某一个段落而不是整条笔记。

*   [可编辑的嵌入](https://github.com/TriliumNext/Trilium/pull/11926)：被包含的文本或代码笔记在宿主笔记内使用完整编辑器进行编辑，一个撤销历史同时覆盖两者。
*   [实时摘录](https://github.com/TriliumNext/Trilium/pull/11925)引用另一条笔记的块。它们保持同步，在摘录中所做的编辑会保存回源笔记。
*   [块引用](https://github.com/TriliumNext/Trilium/pull/12069)链接到段落、标题、表格或块范围。目标打开时会滚动到该块并高亮显示，在共享页面上每个块都有自己的公开链接。

布局跟上了内容。[多栏布局](https://github.com/TriliumNext/Trilium/pull/11958)将两到四栏并排放置，并在窄屏幕上堆叠显示。[绘图画布](https://github.com/TriliumNext/Trilium/pull/11829)使用 Excalidraw 就地绘制并随笔记保存。文件可以[一步附加](https://github.com/TriliumNext/Trilium/pull/11795)，作为 PDF 和电子表格的内联嵌入或作为链接，YouTube 视频和网络音频或视频可在笔记内播放。块手柄可移动块、图片和表格，空行上的“+”可打开斜杠命令，一个[链接对话框](https://github.com/TriliumNext/Trilium/pull/12358)从光标处的弹出窗口为网络链接、笔记链接和锚点提供服务。

包含框本身也进行了[重做](https://github.com/TriliumNext/Trilium/pull/11798)：紧凑的标题行带说明文字、全屏、从嵌入到其笔记的链接及返回、Markdown 以源码、分屏或预览方式包含、代码带折叠和行号，以及通过拖动角或边来调整大小。

由 @adoriandoran 贡献。

### 文本笔记中的表格

表格是编辑器的薄弱环节：没有合并单元格，没有排序，超过几行就意味着要切换到电子表格笔记。[表格上下文菜单](https://github.com/TriliumNext/Trilium/pull/11774)现在可以合并和取消合并单元格、均匀分布列，以及一次插入或删除多行和多列。列按其值排序，日期、时间、数字和文本会根据笔记的语言进行检测和排序，Alt+方向键可移动行和列，同时保持合并单元格和标题行不变。

宽表格在固定表头下横向滚动，在触摸屏上，列栏可调整大小和选择列，角手柄可选择单元格范围。插入表单可接受最大 1000 × 100 的任意尺寸，并支持标题行和标题列。

由 @adoriandoran 贡献。

### 行动前先询问的 AI

有两件事让许多用户远离 AI 集成：按 token 付费，以及将笔记的写入权限交给模型。这两点在本版本中都有所改变。

ChatGPT Codex 订阅（包括免费计划）和 OpenRouter 加入 Claude Code、GitHub Copilot 和 Antigravity 作为提供商，因此现有订阅可以驱动 Trilium 的对话。[自定义搜索引擎](https://github.com/TriliumNext/Trilium/pull/11878)（Brave Search、Tavily、Exa、Serper、Perplexity 或自托管的 SearXNG）为本地模型和自身没有搜索能力的提供商（如 DeepSeek）提供网络搜索。

[在工具运行之前](https://github.com/TriliumNext/Trilium/pull/12116)，对话会显示 AI 即将读取或更改的内容，并等待你允许或拒绝，可以针对该次调用或对话的其余部分。工具菜单设置默认值：始终询问、仅在更改前询问或从不询问。无论使用 API 密钥还是订阅提供商，其工作方式都相同。

### 共享页面看起来像应用

共享到网络的笔记以其自己的主题渲染，共享集合则显示为其子项的普通列表。共享页面现在使用[基于应用自身外观构建的主题](https://github.com/TriliumNext/Trilium/pull/11979)，支持浅色和深色，共享的看板、表格、日历或其他集合以与在 Trilium 内相同的视图渲染。

绘图以主题感知的 SVG 图片显示，而不是下载链接，共享笔记的每个块都有一个公开链接，可从其块手柄复制，打开页面时会滚动到该块。

### 没有侧边栏的移动端

在手机上，侧边栏既是笔记树，也是浏览应用的唯一方式，而且每次打开时都会覆盖笔记。iOS 和 Android 应用获得了[无需侧边栏的导航系统](https://github.com/TriliumNext/Trilium/pull/12279)，iOS 还获得了[重新设计的布局](https://github.com/TriliumNext/Trilium/pull/12263)，采用 iOS 26 的风格。

编辑时，格式工具栏作为紧凑的浮动岛悬浮在笔记上方，仅在你输入时显示，并同时带来小组件、链接和列表工具栏。

## 🔄 兼容性

*   同步协议版本从 39 升至 41：不同版本的实例无法相互同步，因此请同时更新服务器和所有桌面及移动客户端。
    *   [同步协议已扩展，以便重做后的包含笔记在客户端之间同步时不会冒数据丢失的风险，这就是本版本提升其版本号的原因。](https://github.com/TriliumNext/Trilium/pull/11798)
*   数据库版本从 240 升至 242：此版本首次打开数据库时会进行迁移（在自动备份之后），之后较早的版本将拒绝打开它。
*   Docker 镜像已重做，可以以非 root 用户运行。请查看 [Docker 设置文档](https://docs.triliumnotes.org/user-guide/setup/server/installation/docker)中的相应章节。（[#5790](https://github.com/TriliumNext/Trilium/issues/5790)）

## 🚨 破坏性变更

*   旧版布局已被移除。自新布局推出以来已近一年，我们认为它已经足够完善，可以用于日常使用。更多信息请参阅[相应的 GitHub Discussions 帖子](https://github.com/orgs/TriliumNext/discussions/11891)。
*   v0.106.0 中引入的多级 `#sorted` 值现在必须像搜索的 `orderBy` 一样使用 `#` 写入标签：`#sorted="priority desc, dueDate"` 变为 `#sorted="#priority desc, #dueDate"`。不带 `#` 的值将回退为按标题排序。单个名称（`#sorted=myOrder`）和仅属性值（`dateModified desc, title`）不受影响。参见[笔记排序](https://docs.triliumnotes.org/user-guide/concepts/notes/sorting)。
*   如果启用了 TOTP，`POST /etapi/auth/login` 现在需要验证码。更多信息请查看 API 文档。

## ✨ 改进

1.  界面：上下文菜单和笔记自动补全从头重写。菜单获得了[键盘导航](https://github.com/TriliumNext/Trilium/issues/1166)和更好的可访问性，不再[被裁剪](https://github.com/TriliumNext/Trilium/issues/5294)，笔记树菜单更加紧凑。[自动补全](https://github.com/TriliumNext/Trilium/issues/5134)具有现代设计、命令面板、链接和关系选择器、文本和 Markdown 笔记中的 `@` 提及以及属性值建议。（[#5493](https://github.com/TriliumNext/Trilium/issues/5493)、[#11896](https://github.com/TriliumNext/Trilium/pull/11896)、[#11833](https://github.com/TriliumNext/Trilium/pull/11833)）
2.  文本编辑器：[主题自适应颜色：在浅色和深色主题之间切换时，文本、高亮和表格颜色保持清晰可读](https://github.com/TriliumNext/Trilium/pull/11788) 由 @adoriandoran 贡献
3.  文本编辑器：[更智能的粘贴：从 Chrome 和基于 Chromium 的应用程序（例如 VS Code）复制的文本会去除颜色、背景和表格样式。](https://github.com/TriliumNext/Trilium/pull/11854)
4.  桌面：[会议可以在本地转录（实验性），按需下载设备端语音模型，实时音频电平，可复制的转录卡片和同意提醒。](https://github.com/TriliumNext/Trilium/pull/12079)（[#12079](https://github.com/TriliumNext/Trilium/pull/12079)、[#12083](https://github.com/TriliumNext/Trilium/pull/12083)、[#12101](https://github.com/TriliumNext/Trilium/pull/12101)）
5.  集合：[地理地图属性对话框，以图形方式设置图像地图：选择一条图像笔记作为地图（奇幻世界、平面图、校园），在图像自身像素和自定义角坐标之间选择，切换深色样式，并设置地图样式、比例、标签、聚类和嵌套深度，这些以前都是手写的 `#map:*` 属性。](https://github.com/TriliumNext/Trilium/issues/11928)
6.  日历：日历集合赶上了看板：属性对话框、事件上的属性，以及[知道自身年龄](https://github.com/TriliumNext/Trilium/pull/11601)的重复事件。
    *   日历属性对话框在一个地方列出日历的设置（隐藏周末、周数、时间段、已归档笔记）及其事件模板，事件属性卡片选择事件显示哪些属性以及以什么顺序显示。没有人安排过的属性不会出现在事件上，因此现有日历保持其当前的标签。
    *   事件上下文菜单像看板卡片一样就地设置事件的属性，因此无需打开笔记即可更改标志、状态或日期。
    *   年度事件可以显示其已重复了多少年：选择“每年”后，“重复”下拉菜单提供“在标题中显示年数”，它会在事件上写入 `#calendar:titleTemplate="${title} (${years})"`。1990 年录入一次的生日在 2026 年显示为“Ana 的生日 (36)”，并且每年递增。
    *   例行事件（每日站会、午餐）可以通过属性对话框从月、年和列表视图中隐藏。
7.  性能：全面更快：后台和恢复的标签页在首次查看时加载，标签页在鼠标按下时切换，Chromium 和桌面应用不再在每次更改时重新设置整个页面的样式（每次约 30 毫秒），滚动更流畅，画布上的手写慢帧减少了 97%，上传量减少了 80%。（[#12189](https://github.com/TriliumNext/Trilium/pull/12189)、[#12327](https://github.com/TriliumNext/Trilium/pull/12327)、[#12283](https://github.com/TriliumNext/Trilium/pull/12283)、[#12334](https://github.com/TriliumNext/Trilium/pull/12334)、[#12324](https://github.com/TriliumNext/Trilium/pull/12324)）由 @adoriandoran 贡献
8.  界面：重命名：笔记树菜单中的“克隆”现在为“复制”，工具提示说明它会粘贴为克隆（[#12230](https://github.com/TriliumNext/Trilium/pull/12230)，由 @adoriandoran 贡献）；“布尔值”提升属性类型现在为“复选框”（[#11738](https://github.com/TriliumNext/Trilium/issues/11738)）；“打开笔记自定义”现在为“打开方式”，在 Linux 上具有基于门户的应用选择器，支持 macOS，并在笔记更改时提供更清晰的通知（[#7258](https://github.com/TriliumNext/Trilium/issues/7258)、[#12418](https://github.com/TriliumNext/Trilium/issues/12418)）。
