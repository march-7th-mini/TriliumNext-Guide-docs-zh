# v0.104.0：禁用 Electron 中的 Node 集成

## 简介

在 v0.104.0 之前，在渲染器级别执行的代码（例如前端脚本）可以直接引用 `@electron/remote`，甚至可以使用 Node.js API（例如 `process` 或 `fs`）。虽然这使它们功能强大，但也暴露了巨大的攻击面——笔记中的任何 XSS 或不受信任的脚本都会成为主机上的远程代码执行。

为了缓解这种情况，客户端不再能访问这些 API，所有操作都必须通过 <a class="reference-link" href="../Script%20API/Electron%20API.dat">Electron API</a> 进行。

> [!NOTE]
> 如果此 API 变更导致您的一些前端脚本出现问题，请考虑：
> 
> *   与具有更大自由度的 <a class="reference-link" href="../Backend%20scripts.md">后端脚本</a> 进行交互。
> *   将其作为功能请求[报告](../../Troubleshooting/Reporting%20issues.md)。

## API 概述

前端和后端 API 位于全局变量 `api` 中，可以在脚本中的任何位置使用。例如，要向用户显示消息，可以使用以下前端脚本：

```javascript
api.showMessage("Hello world.");
```

Electron API 则不同：它位于 `window.electronApi` 上（由桌面预加载脚本暴露），而不是在 `api` 上，并且仅在 Electron 桌面版中可用。使用它的前端脚本应使用 `if (window.electronApi)` 进行保护，以便它们在浏览器和独立（WASM）构建中也能正常降级。

```javascript
window.electronApi?.window.setZoomFactor(1.2);
```

## 额外保护

某些 API 内置了额外的安全防护措施，以防止未经授权的访问。

`shell` 组是验证最严格的：`openExternal` 仅限于允许列表中的 URL 方案（阻止 `file:`、`smb:`、Follina 类方案等），`openPath` 必须解析到 Trilium 数据目录或临时目录下，而 `downloadURL` 则锁定到应用自身的源。无效输入会在主进程侧抛出异常，而不是被静默传递。
