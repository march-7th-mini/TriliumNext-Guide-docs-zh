# 数据库

数据库是 Trilium 中最重要的概念之一。它保存了所有笔记、属性、代码脚本等。因此，了解数据库的运作方式以及如何正确备份数据库至关重要。

## 数据库引擎

Trilium 使用 [SQLite](https://www.sqlite.org/) 作为其数据库引擎。SQLite 是一个嵌入式数据库，这意味着它不需要单独的服务器进程，而是直接集成到 Trilium 应用程序中。数据库本身存储在一个单独的文件中，通常位于 Trilium 的[数据目录](../数据目录.md)内。

## 数据库文件

数据库文件通常命名为 `document.db`。该文件包含所有笔记、属性、代码脚本、选项等。因此，备份此文件对于防止数据丢失至关重要。

## 备份

Trilium 提供了多种备份数据库的方法。这些方法包括：

*   [自动备份](../备份.md#自动备份)
*   [每日备份](../备份.md#每日备份)
*   [手动备份](../备份.md#手动备份)

## 压缩数据库

随着时间推移，数据库可能会变得碎片化并占用比实际需要更多的磁盘空间。为了优化数据库并减小其大小，Trilium 提供了“压缩数据库”功能。此功能会重建数据库文件，从而消除碎片并回收未使用的空间。

要压缩数据库，请转到“设置” -> “高级” -> “压缩数据库”。

## 数据库匿名化

Trilium 还提供了“数据库匿名化”功能。此功能会创建数据库的副本，其中所有笔记内容、标题和属性都会被替换为匿名数据。此功能主要用于调试和错误报告，因为它允许用户共享数据库结构而不会泄露敏感信息。

要使用此功能，请转到“设置” -> “高级” -> “数据库匿名化”。

## 数据库的完整性

Trilium 在启动时会自动检查数据库的完整性。如果检测到任何问题，它会尝试修复它们。如果修复失败，Trilium 将显示错误消息并可能拒绝启动。

## 数据库加密

Trilium 支持数据库加密。如果启用了加密，数据库文件将使用密码进行加密。这意味着即使有人获得了数据库文件的访问权限，如果没有密码，他们也无法读取其内容。

要启用加密，请转到“设置” -> “高级” -> “加密”。

## 数据库迁移

在 Trilium 升级期间，可能需要对数据库进行迁移。迁移过程会更新数据库结构以匹配新版本的 Trilium。此过程通常是自动的，但在某些情况下可能需要手动干预。

## 故障排除

如果遇到与数据库相关的问题，可以尝试以下步骤：

*   **检查数据库文件**：确保数据库文件存在且未被损坏。
*   **检查磁盘空间**：确保磁盘上有足够的可用空间。
*   **查看后端日志**：后端日志可能包含有关数据库错误的详细信息。
*   **尝试修复数据库**：Trilium 在启动时会自动尝试修复数据库问题。
*   **从备份中恢复**：如果其他方法都失败，可以从备份中恢复数据库。
