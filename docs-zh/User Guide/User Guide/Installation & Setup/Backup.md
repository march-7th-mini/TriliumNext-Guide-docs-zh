# 备份

Trilium 支持简单的备份方案，它会在以下事件发生时保存一份 <a class="reference-link" href="../Advanced%20Usage/Database.md">数据库</a> 的副本：

*   每天一次
*   每周一次
*   每月一次
*   在数据库迁移到新版本之前

因此，您总共最多会有来自不同时间点的 4 个备份，这应该能保护您免受各种问题的影响。这些备份默认存储在 [数据目录](Data%20directory.md) 中的 `backup` 目录下。

这只是一个非常基础的备份解决方案，我们建议您添加一些更好的备份方案——例如，将 <a class="reference-link" href="../Advanced%20Usage/Database.md">数据库</a> 备份到云端/其他计算机等。

请注意，<a class="reference-link" href="Synchronization.md">同步</a> 由于其将数据分发到其他计算机的特性，也提供了一些备份能力。

## 创建备份

### 在桌面应用和 Web 客户端上：

1.  转到 **设置 → 备份**，然后按 **立即备份** 按钮。
2.  备份创建过程可能需要一些时间，尤其是对于较大的数据库。备份完成时会收到通知。
3.  备份将作为 **backup-now** 保存在 **现有备份** 列表中，您可以在其中下载它。

### 在独立客户端上

1.  转到 **设置 → 备份**，然后按“**下载备份**”按钮。
2.  系统会提示您 **重启应用**。确认后，应用将自动重启。
3.  设置 **备份名称** 或 **密码**（均为可选），然后按“**继续**”。
4.  按“**生成并下载**”按钮，等待下载完成。
5.  确认下载已保存到您的设备后，按“**完成**”以结束操作。

## 下载备份

*   **桌面和 Web 客户端**：要下载现有备份，请导航到 **设置 → 备份 → 现有备份**，然后选择 **下载**。
*   **独立客户端**：此版本不支持自动备份。您可以通过转到 **设置 → 备份 → 下载备份** 手动创建并下载备份。

## 恢复备份

*   **对于新的 Trilium 实例**：在设置新的 Trilium 实例时，使用设置菜单中的“从备份恢复”选项，它将引导您完成恢复现有备份的过程。
*   **对于现有的 Trilium 实例**：要恢复备份并替换当前数据库，请转到 **设置 → 备份**，然后点击 **恢复备份**。系统会提示您重启应用以开始恢复过程。重启后，您可以选择在覆盖前备份现有数据库。注意：对于 Web 客户端，请使用“重新开始”功能（**设置 → 数据库 → 重新开始**）切换到设置屏幕并恢复备份。

接下来，从您的设备中选择备份文件（.db 或 .tnbackup）。Web 客户端针对处理大型备份进行了优化，并且与桌面应用类似，能够适应不稳定的网络状况。

如果您的数据库已加密，系统会提示您输入用于加密备份文件的密码。如果没有正确的密码，则无法进行解密和恢复。

恢复备份可能需要一些时间，具体取决于其大小。完成后，Trilium 将打开刚刚恢复的数据库。

### 恢复备份的替代方法

假设您想恢复每周备份（仅限 .db 格式，此方法不支持 .tnbackup 文件），操作方法如下：

*   找到 Trilium 使用的 [数据目录](Data%20directory.md) - 简单的方法是点击左上角“菜单”中的“关于 Trilium Notes”，然后查看“数据目录”
    *   从现在开始，我将 `~/trilium-data` 称为数据目录
*   找到 `~/trilium-data/backup/backup-weekly.db` - 这是 <a class="reference-link" href="../Advanced%20Usage/Database.md">数据库</a> 备份。
*   此时停止/终止 Trilium
*   删除 `~/trilium-data/document.db`、`~/trilium-data/document.db-wal` 和 `~/trilium-data/document.db-shm`（后两个文件是自动生成的）
*   将此 `~/trilium-data/backup/backup-weekly.db` 复制并重命名为 `~/trilium-data/document.db`
*   确保该文件可写，例如使用 `chmod 600 document.db`
*   重新启动 Trilium

> [!WARNING]
> 如果您配置了同步，则需要在同步集群的所有成员上执行此操作，否则旧版本（恢复的备份）的文档将被检测到并同步到新版本。

## 更改 Trilium 中的备份位置（仅限桌面版）

从 0.105 版本开始，Trilium 桌面客户端允许用户更改备份存储的目录。请按照以下步骤指定自定义备份目录：

1.  导航到 **设置** → **备份位置**。
2.  点击 **选择位置** 按钮。
3.  在您的文件系统上选择任何可写目录。根据您的操作系统，这可能包括网络共享。

设置自定义目录后，所有手动和自动备份都将保存到该位置。如果所选目录不可用，备份可能会失败或回退到默认位置。

> [!TIP]
> 为了在备份位置不安全时获得更好的隐私保护，您可以启用备份加密，这会使备份文件在没有正确密码的情况下不可读。

## 备份加密

Trilium 可以保护数据库备份的全部内容，确保在未提供正确密码的情况下无法读取。这对于将备份存储在不安全的位置（如网络共享、未加密的外部驱动器或云服务）特别有用。

加密的数据库备份使用 Trilium 备份容器（.tnbackup）格式，该格式依赖于 AES-256-GCM。这种经过身份验证的加密模式会打乱数据，并生成一个标签来确认数据未被更改。密码本身不直接用作密钥；它通过 scrypt（一种设计为缓慢且占用大量内存的密钥派生函数）进行处理，即使使用强大的硬件也难以进行暴力破解密码猜测。每个备份还会收到一个随机的 16 字节盐，确保相同的密码永远不会产生相同的加密密钥两次。此外，诸如块顺序、长度和头部标志等关键元数据在加密过程中被密码学绑定（通过“附加认证数据”），以防止诸如重排、截断或拼接等未被检测到的篡改。

### 启用备份加密

要在桌面应用中为自动备份启用加密：

1.  转到 **设置 → 备份 → 备份选项**。
2.  点击 **开启加密** 并设置密码。

启用加密后，所有新创建的备份（自动和手动）都将使用指定的密码进行加密。在启用加密之前创建的备份将保持不安全状态。

您可以随时使用 **更改密码** 按钮更改密码。新密码将适用于更改后创建的备份。

要禁用加密，请取消选中 **设置 → 备份 → 启用加密**。

> [!NOTE]
> 在某些系统上，可能没有可用的密钥环供 Trilium 安全存储加密密码。在这种情况下，加密选项将被禁用。

## 备份压缩

数据库备份可以选择压缩以最小化存储占用。此方法主要在处理主要由文本内容组成的数据库时有效。但是，媒体文件（图像、视频、音频）以及 PDF、ODF 和 DOCX 文件已经在其原始格式中进行了压缩，进一步压缩不会带来好处。

压缩备份使用 Trilium 备份容器（.tnbackup）存储，采用 RFC 1952 GZIP 压缩。

> [!WARNING]
> **注意：** 压缩会增加备份创建和恢复所需的时间。它还可能导致自动备份期间 CPU 使用率升高，从而可能更快地耗尽电池供电设备的电量。仅在必要时启用此选项。

### 启用备份压缩（仅限桌面版）

要为新的自动和手动备份启用压缩，请导航到 **设置 → 备份 → 备份选项**，然后将 **启用压缩** 切换为开启。

## 禁用备份

虽然不推荐这样做，但可以在 [数据目录](Data%20directory.md) 中的 `config.ini` 中禁用备份：

```
[General]
... some other configs
# set to true to disable backups (e.g. because of limited space on server)
noBackup=true
```

您也可以查看 [配置](../Advanced%20Usage/Configuration%20\(config.ini%20or%20environment%20variables\).md) 文件，以了解如何将所有 `config.ini` 值作为环境变量提供。

参见 [示例配置](https://github.com/TriliumNext/Trilium/blob/master/config-sample.ini)。
